# Краткий принцип работы (Трехступенчатый алгоритм)
 
Скрипт не качает файлы "вслепую". Он работает в 3 ступени, чтобы экономить трафик, место на диске и не получать бан от Яндекса:

1. **СТУПЕНЬ 1 (Кэш дерева):** Скрипт запрашивает у API Яндекса структуру всех папок и файлов по вашей ссылке. Сохраняет эту карту в изолированную базу данных SQLite (`db/<имя_контейнера>.db`).
2. **СТУПЕНЬ 2 (Сверка):** Скрипт инкрементально сканирует ваш локальный диск (проверяя время изменения `mtime`), сравнивает с кэшем Яндекса. Если файл уже скачан — пропускает. Если файла нет — добавляет в очередь на скачивание в БД.
3. **СТУПЕНЬ 3 (Скачивание):** Скрипт берет файлы из очереди и скачивает их. Большие файлы качаются в несколько потоков, склеиваются и проверяются на целостность размера.

## Базовый запуск

./yadpylesos '<Имя_контейнера>' '<Ссылка_Яндекс>' '<Папка_назначения>' [Кол-во_файлов] [Опции]

**Пример:**

./yadpylesos 'my_archive' 'https://disk.yandex.ru/d/aBcDeFgH' '/share/Container/downloads/' 500 -v --threads=4

## Описание аргументов

Аргументы передаются по порядку. Первые три — обязательные.

*   `<Имя_контейнера>` (в кавычках)
    Уникальное имя для этого процесса. Используется как имя Docker-контейнера и как имя файла БД (например, `db/my_archive.db`). Нельзя использовать пробелы.
*   `<Ссылка_Яндекс>` (в кавычках)
    Ссылка на публичную папку Яндекс.Диска (начинается с `https://disk.yandex.ru/d/`).
*   `<Папка_назначения>` (в кавычках)
    Локальный путь на вашем сервере (NAS), куда будут скачаны файлы. Должен начинаться со слеша `/`.
*   `[Кол-во_файлов]` (необязательный)
    Ожидаемое количество файлов. Нужно только для корректного отображения прогресс-бара. Если не знаете, ставьте `0` или не указывайте.

## Описание опций (флагов)

Опции можно добавлять в любом порядке после обязательных аргументов. Флаги со значениями пишутся через знак `=` (например, `--threads=4`).

### Режимы работы:
*   `-v` или `--verbose`
    Подробное логирование. В консоль будут выводиться имена каждого пропущенного и скачиваемого файла, а также обход папок.
*   `--batch`
    Пакетный режим (Менеджер ссылок). Запускается без аргументов: `./yadpylesos --batch`. Открывает интерактивное меню на Python для управления списком ссылок в файле `source_links.txt` (добавлять, удалять, редактировать, вкл/выкл) и скачивает активные ссылки последовательно.
*   `--batch-auto`
    Автоматический пакетный режим для cron. Качает активные ссылки из `source_links.txt` без интерактивного меню.
*   `--build-queue`
    Выполнить только Ступень 1 и Ступень 2. Скрипт обновит кэш, сверится с диском и сохранит очередь скачивания в базу, после чего завершит работу. Скачивание (Ступень 3) не запускается.

### Скачивание и потоки:
*   `--threads=N`
    Количество потоков для скачивания одного файла (по умолчанию: `1`, максимум: `8`). Многопоточное скачивание включается только для файлов крупнее порогового значения. Оптимизировано для HDD RAID массивов.
*   `--multithread-size=MB`
    Минимальный размер файла в Мегабайтах, при котором включается многопоточное скачивание (по умолчанию: `100`).
*   `--quantity-files=N`
    Количество одновременных файлов для скачивания (по умолчанию: `1`). Для SSD можно `3-5`, для HDD строго `1`.

### VPN и Сеть:
*   `--vpn`
    Принудительно запускать VPN-туннель (mihomo) при старте скрипта. Весь трафик (API и CDN) пойдет через VPN. Требует наличия файлов `link*.txt` со ссылками `vless://` или `trojan://` в папке `vpn/`, либо готового `config.yaml`.
*   `--ssl-off`
    Отключить проверку SSL-сертификатов. Обход для багов Яндекс.Диска, когда сервера хранения (`storage.yandex.net`) отдают просроченные сертификаты.
*   `--homeostasis-off`
    Отключить гомеостаз (автоматическое снижение потоков при высокой нагрузке на ЦП/Диск).
*   `--simulate-ban`
    Скрытый флаг для тестирования работы модуля VPN. Эмулирует бан API (ошибку 429) и обрывы связи.
*   `--trace-mem`
    Включить профилировщик памяти (tracemalloc). В конце работы выведет Топ-10 строк кода, потребляющих больше всего RAM.

### Управление кэшем и базой:
*   `--refresh-cache`
    Принудительно обновить кэш дерева (Ступень 1). Скрипт проигнорирует старый кэш в БД и заново запросит всю структуру у API Яндекса.
*   `--db-stats`
    Вывести статистику всех баз данных (сколько файлов в кэше, сколько в очереди) и выйти.
*   `--db-check`
    Глубокая проверка целостности всех баз данных SQLite.
*   *(Очистка данных)*: Чтобы удалить кэш и историю скачивания конкретной ссылки, просто удалите файл `db/<имя_контейнера>.db` в папке проекта.

### Авторизация и безопасность:
*   `--auth-enable`
    Включить глобальную авторизацию (OAuth 2.0) для всех ссылок по умолчанию. Требует наличия файла `auth/.yad_token`.
*   `--auth-disable`
    Отключить глобальную авторизацию. Скрипт будет качать анонимно.

### Дополнительные функции:
*   `--md5='имя_файла'`
    Проверка MD5-хэша конкретного файла. Скрипт найдет файл в кэше, запросит его хэш у Яндекса, посчитает локальный хэш и сравнит их.
*   `--move-extra='/путь/к/карантину/'`
    Перенос локальных файлов, удаленных с Яндекса (осиротевших), в указанную папку. Если флаг не указан, осиротевшие пустые (0-байтные) файлы просто удаляются.
*   `--notify-tg`
    Отправить итоговый отчет в Telegram по завершении работы скрипта. (Требует предварительной настройки Telegram-бота).

## Настройка Telegram-уведомлений

Для использования флага `--notify-tg` необходимо настроить бота:

1. **Создайте бота:** Напишите в Telegram боту `@BotFather`, создайте нового бота (команда `/newbot`) и получите HTTP API Token.
2. **Узнайте свой Chat ID:** Напишите любому боту, показывающему ID (например, `@getmyid_bot`), и узнайте свой Chat ID.
3. **Создайте файл конфигурации:** В папке `auth/` создайте файл `tg_config.yaml` со следующим содержимым:
   ```yaml
   telegram:
     bot_token: "ВАШ_ТОКЕН_ОТ_BOTFATHER"
     chat_id: "ВАШ_CHAT_ID"
   ```

После настройки при запуске с флагом `--notify-tg` скрипт автоматически (при необходимости включив VPN) отправит вам подробный отчет о скачивании в Telegram.

## Полезные команды

**Просмотр логов работающего контейнера:**

docker logs -f ИмяКонтейнера

*(Для выхода из логов нажмите Ctrl+C, контейнер продолжит работу в фоне).*

**Остановка и удаление зависшего контейнера:**

docker stop ИмяКонтейнера && docker rm -f ИмяКонтейнера

**Очистка папки логов:**

rm -f report/*.txt
