**Я.Д-Пылесос / YA.D-Pylesos**

Я.Д-Пылесос / YA.D-Pylesos — утилита для скачивания с Яндекс.Диска на Linux ARM64 (QNAP NAS) и AMD64 (Fedora WS). 
Код написан полностью с использованием AI-Assisted Development (LLM). В проекте автор выступает в роли Product Owner / Project Manager / System Architect / QA Engineer.
@serbambr 

## Возможности

*   **Модульная архитектура (Мультивендорность):** Логика API вынесена в отдельные модули (`apiyandex.py`, `apimail.py`). Ядро скрипта не знает, как работает конкретный облако-провайдер, оно просто вызывает стандартный интерфейс. Подготовлена заглушка для Mail.ru.
*   **Трехступенчатый алгоритм работы:** Инкрементальное сканирование диска (Mark and Sweep) -> Сверка данных с API (с использованием кэша в SQLite) -> Многопоточное скачивание.
*   **Изоляция БД (BL-DB-Split):** Каждая ссылка использует свою базу данных SQLite (`db/<имя_контейнера>.db`). Полное отсутствие блокировок `database is locked` при параллельной работе. Очистка данных — простым удалением файла БД.
*   **Умный авто-VPN (mihomo):** Вынесен в отдельный модуль `vpn_manager.py`. При срабатывании бана API (429) скрипт генерирует YAML-конфиг из `link*.txt` (VLESS/Trojan/Reality), запускает туннель и маршрутизирует трафик. Встроенный API Watchdog перезапускает туннель при зависании. Записывает аудит-лог смены IP-адресов.
*   **Гомеостаз 3.0 (Мониторинг железа):** Флаг `--trace-status` выводит панель состояния раз в 60 секунд: температура CPU, частота, Load Average, потребление RAM хостом, задержки записи на диск (I/O Latency), свободные иноды. При перегрузке диска или CPU скрипт автоматически снижает потоки.
*   **База Телеметрии (Опыт):** Глобальная `db/telemetry.db` собирает агрегированные итоги каждой сессии (пиковые температуры, среднее время ответа API, количество банов). Защита от переполнения (автоочистка старше 30 дней).
*   **Конфигурация через `.env` (SSOT):** Все лимиты, таймауты, DNS, пути к сенсорам температуры и настройки Docker вынесены в единый файл `.env`. 
*   **Бережливость HDD (RAID-friendly):** Многопоточное скачивание реализовано через запись в изолированные `.part.*` файлы с последующей атомарной склейкой (`os.replace`).
*   **Железобетонный Анти-бан:** Адаптивные гауссовские паузы (AIMD), парсинг HTTP-заголовка `Retry-After`, ротация User-Agent, детекция "тихого" бана (HTML вместо JSON).
*   **Безопасность данных:** Проверка целостности по MD5, строгая валидация аргументов (Zero Trust). Внутри Docker-контейнера используется `non-root` пользователь. Защита от параллельного запуска через `.pid` файлы (Bulkhead).
*   **Менеджер ссылок (Python CLI) и `--batch`:** Интерактивное управление списком `source_links.txt` с автодополнением по Tab. Пакетный режим отвязывается от терминала по `Ctrl+C`: скрипт уходит в фон и продолжает скачивать ссылки по очереди, выводя точный отчет об оставшихся контейнерах.
*   **Предзапускное меню (Poka-Yoke):** Перед началом скачивания скрипт выводит красивую цветную сводку всех параметров и запрашивает подтверждение пользователя.
*   **Умные уведомления в Telegram:** Флаг `--notify-tg` для отправки итогового отчета. При сбоях скрипт анализирует ошибку (нет места на диске, занят порт, бан API) и отправляет в Telegram переведенное на понятный язык сообщение, а не сырой лог.

## Служебные команды
*   `--auth-status`: Изолированная проверка валидности OAuth-токена и Cookies (делает прямые тестовые запросы к API).
*   `--db-stats`: Вывод статистики по всем базам данных (включая историю телеметрии).
*   `--vacuum`: Сжатие и оптимизация всех баз данных SQLite (VACUUM).

## Быстрый старт

1.  **Подготовка конфигурации:**
    Создайте файл `.env` в корне проекта (пример настроек смотрите в `.env.example`).
2.  **Сборка Docker-образа:**
    docker build -t yadpylesos-slim -f Dockerfile.yadpylesos-slim .
3.  **Менеджер ссылок (Пакетный режим):**
    ./yadpylesos.sh --batch
4.  **Обычное скачивание (с мониторингом и уведомлениями):**
    ./yadpylesos.sh 'test' 'https://disk.yandex.ru/d/...' '/path/to/destination/' 100 -v --threads=4 --trace-status --notify-tg
