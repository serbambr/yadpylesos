# Я.Д-Пылесос — Руководство пользователя (USAGE)

## Краткий принцип работы (Трёхступенчатый алгоритм)

Скрипт не качает файлы «вслепую». Он работает в 3 ступени, чтобы экономить трафик, место на диске и не получать бан:

1. **СТУПЕНЬ 1 (Кэш дерева):** Скрипт запрашивает у API Яндекса структуру всех папок и файлов по ссылке. Сохраняет карту в изолированную БД SQLite (`db/<имя_контейнера>.db`).
2. **СТУПЕНЬ 2 (Сверка):** Инкрементальный скан локального диска (по `mtime`), сверка с кэшем Яндекса. Скачанное — пропускается, отсутствующее — в очередь.
3. **СТУПЕНЬ 3 (Скачивание):** Очередь скачивается. Большие файлы — многопоточно, со склейкой и проверкой целостности размера.

Для YouTube и Boosty подсистема отдельная: структура канала/плейлиста/поста берётся yt-dlp, скачанное учитывается в архиве (`history/youtube.com.txt` / `history/boosty.to.txt`).

## Установка

```bash
./install.sh
```
Создаст структуру каталогов (config/, db/, report/, vpn/, history/, backup/), шаблон `.env`, соберёт Docker-образ и создаст ярлык `yadpylesos`. После установки настройте `.env` (как минимум `DNS_SERVERS`).

## Базовый запуск

```bash
./yadpylesos '<Имя_контейнера>' '<Ссылка_на_источник>' '<Папка_назначения>' [Кол-во_файлов] [Опции]
```

**Пример (Яндекс):**
```bash
./yadpylesos 'my_archive' 'https://disk.yandex.ru/d/aBcDeFgH' '/share/Container/downloads/' 500 -v --threads=4
```

**Пример (YouTube):**
```bash
./yadpylesos 'mychannel' 'https://www.youtube.com/@name/videos' '/share/downloads/yt' 0 -v --notify-tg
```

**Пример (Boosty):**
```bash
./yadpylesos 'mypost' 'https://boosty.to/<автор>/posts/<id>' '/share/downloads/boosty' 0 -v
```

## Описание аргументов

Первые три — обязательные.

*   `<Имя_контейнера>` — уникальное имя процесса. Становится именем Docker-контейнера и файлом БД (`db/my_archive.db`). Без пробелов.
*   `<Ссылка_на_источник>` — публичная ссылка Яндекс.Диска (`https://disk.yandex.ru/d/...`) **или** YouTube (`https://www.youtube.com/@канал/videos`, плейлист `playlist?list=...`, одиночное видео `watch?v=...`) **или** Boosty (пост `https://boosty.to/<автор>/posts/<id>`). Провайдер определяется автоматически.
*   `<Папка_назначения>` — локальный путь на NAS, начинается с `/`.
*   `[Кол-во_файлов]` — ожидаемое число файлов (только для прогресс-бара). Не знаете — ставьте `0`.

## Флаги

Полный список — `./yadpylesos -h`. Основные:

### Режимы работы
*   `-v` / `--verbose` — подробный лог (каждый файл, каждая папка).
*   `--batch` — интерактивный менеджер ссылок (`config/source_links.txt`): add/del/edit/toggle/run/exit, Tab-автодополнение, сохранение на хост.
*   `--batch-auto` — автоматический пакетный режим для cron (без меню).
*   `--build-queue` — выполнить Ступени 1–2 и выйти (очередь в БД, без скачивания).
*   `--refresh-cache` — принудительно перестроить кэш дерева Яндекса и выйти.
*   `--force` — игнорировать архив скачанного: докачается то, чего физически нет на диске. Существующие файлы не перезаписываются.
*   `--unattended` — тихий режим без интерактивных подтверждений (для cron).

### Скачивание и потоки
*   `--threads=N` — потоки на один файл (1–8, по умолчанию 1). Включается для файлов крупнее порога. Оптимизировано для HDD RAID.
*   `--multithread-size=MB` — порог многопоточности в МБ (по умолчанию 100).
*   `--quantity-files=N` — параллельных файлов (по умолчанию 1; SSD — можно 3–5, HDD — 1).

### VPN и сеть
*   `--vpn` — принудительный VPN при старте: весь трафик API/CDN через туннель Xray из `vpn/link*.txt` (VLESS/Trojan/Hysteria, Reality). Порты SOCKS/HTTP — из `PROXY_PORT` в `.env` (по умолчанию 10808/10809).
*   `--vpn-test` — протестировать все серверы пула: таблица с IP и статусом.
*   `--ssl-off` — отключить проверку SSL (обход просроченных сертификатов серверов Яндекса).
*   `--homeostasis-off` — отключить автоматическое снижение потоков.
*   `--simulate-ban` — тестовый флаг: эмулирует бан API для проверки VPN-переключения.

### Кэш и базы
*   `--db-stats` — статистика всех БД + телеметрия (блоками по провайдерам).
*   `--db-check` — проверка целостности всех БД.
*   `--vacuum` — сжатие всех БД (VACUUM).
*   Удаление кэша/истории конкретной ссылки: удалить файл `db/<имя_контейнера>.db`.
*   Для YouTube: удалить/очистить `history/youtube.com.txt` = «перепроверить всё с нуля» (файлы на диске не трогаются). Для Boosty — аналогично `history/boosty.to.txt`.

### Авторизация
*   `--auth-enable` / `--auth-disable` — включить/выключить OAuth для Яндекса (токен в `auth/.yad_token`).
*   `--auth-status [ссылка]` — изолированная проверка валидности токена и куков (включая Boosty).

### Дополнительно
*   `--md5='имя_файла'` — сверка MD5 файла с Яндексом (по кэшу дерева).
*   `--move-extra='/путь/карантина/'` — перенос осиротевших файлов (удалённых с Яндекса) вместо удаления пустых.
*   `--notify-tg` — итоговый отчёт в Telegram (с ретраями отправки).
*   `--trace-mem` — профилировщик памяти (Топ-10 потребителей RAM).
*   `--trace-status` — панель состояния раз в 60 сек (ЦП/Load/RAM/IO/иноды).

## Работа с Boosty

Boosty поддерживается через yt-dlp-подсистему (тот же конвейер, что YouTube).

### Формат ссылок
Работает ссылка на **конкретный пост**: `https://boosty.to/<автор>/posts/<id>`. Ссылки вида `/media/video/...` или фид-ссылки (`?isFromFeed=true`) **не поддерживаются** — используйте ссылку поста (открыть пост в браузере и скопировать адрес).

Один пост = одна галерея: если в посте несколько видео — скачаются все (как плейлист).

### Куки (обязательны для закрытых постов)
1. Вкладка boosty.to → войдите в аккаунт (уровень подписки должен включать нужный контент).
2. Плагином «Get cookies locally» экспортируйте куки вкладки.
3. Положите файл как `auth/boosty.to.txt`.

Проверка: `./yadpylesos --auth-status 'https://boosty.to/<автор>/posts/<id>'` — должен показать «сессия обнаружена».

### Качество и имена файлов
Форматы Boosty именованные (`full_hd` и т.п.) — yt-dlp берёт лучший доступный. Имена файлов включают идентификатор элемента (`Название [id].ext`) — защита от коллизий в медиа-галереях постов.

### Архив
Архив скачанных постов — `history/boosty.to.txt` (ведётся автоматически, повторные запуски докачивают только новое).

## Работа с YouTube

### Типы ссылок
Канал (`@имя/videos`), плейлист, одиночное видео. Скачивается: видео mp4/mkv (максимальное доступное качество), субтитры ru/en (включая автогенерацию), обложка и метаданные, SponsorBlock-вырезки.

### Куки (авторизация YouTube)
Без куков качается только публичный контент без ограничений. Для 18+ и приватного — куки залогиненного аккаунта:

1. Открой **инкогнито-вкладку** браузера, войди в аккаунт YouTube (аккаунт должен иметь подтверждённый возраст).
2. На открытой вкладке youtube.com экспортируй куки плагином «Get cookies locally» → получишь `youtube.com.txt` в формате Netscape.
3. **Сразу закрой инкогнито-вкладку** (не выходя из аккаунта) и больше этой сессией не пользуйся — иначе YouTube ротирует куки и файл протухнет.
4. Положи файл в `auth/youtube.com.txt`.

Дальше файл **самообслуживается**: yt-dlp обновляет сессионные куки в нём при каждом запуске. Не смотри YouTube в браузере под тем же аккаунтом во время скачиваний (гонка ротации).

**Признаки протухания:** Telegram-уведомление «Куки ротированы» или 18+ перестал качаться → повторить экспорт (раз в несколько недель).

### Качество и ограничения
*   Обычные видео — максимальное доступное качество (AV1/VP9/H264+аудио, склейка).
*   **18+ видео: потолок 360p** (формат 18) — ограничение SABR-политики YouTube для возрастного контента, не дефект программы. PO-провайдер (bgutil) внедрён и защищает от bot-check.

### Архив и повторные запуски
Архив `history/youtube.com.txt` хранит ID скачанного: повторные запуски докачивают только новое. Обрывки прошлых сессий (`.part`, `.fNNN.*`, `.temp.*`) старше часа очищаются автоматически при запуске.

### Внутренняя инфраструктура (без участия пользователя)
Node.js-решатель JS-челленджей YouTube (persistent-кэш на хосте, сеть не нужна), PO-провайдер bgutil (порт 4416, поднимается на время сессии, лог `report/bgutil_provider.log`), SponsorBlock API.

## VPN

*   Пул серверов: файлы `vpn/link*.txt` (VLESS/Trojan/Hysteria). Файлы с префиксом `_` — выключены.
*   Автоматические режимы: при бане API — туннель поднимается/ротация серверов; при `--vpn` — с самого старта.
*   Проверка пула: `./yadpylesos --vpn-test`.
*   Аудит смен IP: `report/vpn_audit.log`.

## Telegram-уведомления

1. `@BotFather` → `/newbot` → получить HTTP API Token.
2. Узнать свой Chat ID (например, через `@getmyid_bot`).
3. Создать `auth/tg_config.yaml`:
```yaml
telegram:
  bot_token: "ВАШ_ТОКЕН_ОТ_BOTFATHER"
  chat_id: "ВАШ_CHAT_ID"
```
Отправка идёт через VPN при необходимости, с 3 попытками. Отчёты: успех/ошибка с переведённой причиной (нет места, куки ротированы, рейт-лимит и пр.).

## Обслуживание

**Просмотр логов:**
```bash
docker logs -f ИмяКонтейнера
```
(Ctrl+C — выход из просмотра, контейнер продолжает работу). Детальный лог сессии — файл `report/<имя>_<дата>.txt` — источник истины (консоль docker logs может отображать строки со склейками).

**Остановка зависшего контейнера:**
```bash
docker stop ИмяКонтейнера && docker rm -f ИмяКонтейнера
```

**Очистка логов:** авто (старше 14 дней) или `rm -f report/*.txt`.

**Проверка качества кода (для разработчика):**
```bash
./check.sh
```

**Карантин осиротевших файлов:** при обычном запуске 0-байтовые удаляются; для переноса в папку анализа — `--move-extra='/путь/'`.
